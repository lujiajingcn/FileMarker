## 三、真正值得关注的问题（跨组合归纳）

T1/T2 的「问题」多数是顺序本身不成立；真正与软件质量相关的集中在下面 4 条：

### 1. 目录被当成文件打标签（B2 / F8 / F9 / T1 / T2 / F11 / L11 都可能碰到）

`getSelFilePath()` 不过滤目录，拖拽/添加/清除标签都按「选中项」处理。
目录被写上 ADS 标签后：标签列会显示芯片，但 ✕ 与「编辑标签…」对目录直接 return，**看得见、改不掉**；搜索只扫文件，**搜不到**。
只有「清除选中文件的标签」能清掉（该路径没过滤目录）。

### 2. 标签一改，整个遍历根的缓存作废

任何标签修改都会 `invalidateCacheForFile()` → 反查遍历根 → 删除整个根的缓存行。
于是「改 1 个文件的标签，下次搜该目录要全盘重扫」，界面只表现为结果页变成「结果来自磁盘扫描」。

### 3. 结果页改完标签，列表不刷新

`S8 编辑标签 / S9 清除标签` 之后，结果行标签芯片仍是旧值；如果因此不再匹配条件，该行也不会消失。
（本全集文件因为顺序限制，不会出现 S8/S9 之后操作同一结果行的组合，但实际使用会遇到。）

### 4. 撤销只保留最近一次（T4 共 21 组）

两次连续改标签，撤销点被后者覆盖，`Ctrl+Z` 只能撤销最后一次。属现有设计，但在「拖动打标 → 编辑标签」这类连续操作里最容易被察觉。

## 四、判定规则（可复核）

| 规则 | 触发条件 | 归入 |
|---|---|---|
| R1 页面入口 | 操作入口所在页（文件列表/结果页/进度页）≠ 当前页 | T1 |
| R2 前置条件 | 未选中文件 / 未选中标签 / 结果为空 / 无进行中任务 / 无可撤销 | T2 |
| R3 进程终止 | `G4 退出` 之后仍有操作 | T3 |
| R4 撤销覆盖 | 连续两个会改标签的操作 | T4 |
| R5 其它 | 以上都不触发 | T5 |

补充约定：任务（搜索/遍历/AI）启动后，默认「用户等它跑完」再执行下一步；
只有紧接其后的进度页操作（P1–P4）或点左侧目录（N1）才视为「任务进行中操作」。

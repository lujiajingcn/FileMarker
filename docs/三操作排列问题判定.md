## 三、关键发现

### 1. 三步窗口太短，搜索类流程根本装不下

要完整走一次搜索：先选标签（L1）→ 搜索（B4）→ 用结果（S3/S4…），这已经是 3 步；
再加上「打开文件/编辑标签」就必然超窗。所以在 3 步内，
**没有任何一条排列能同时包含「选标签 + 搜索 + 使用结果行」**——这类流程至少需要 4 步。

### 2. 无问题的 58208 组里，超过八成没有实际作用

| 类型 | 组数 | 占比（占 T5） |
|---|---|---|
| 有明确目的（选择→操作、搜索→结果、改标签→撤销等） | 9975 | 17.14% |
| 纯导航/查看/条件设置（不改变任何数据） | 48233 | 82.86% |

### 3. 最容易在第 3 步失败的入口

| 操作 | 作为失败步出现次数 |
|---|---|
| `S1` 返回目录 | 8599 |
| `S2` 重新扫描 | 8599 |
| `S3` 双击结果行打开 | 8599 |
| `S4` 结果页打开 | 8599 |
| `S5` 结果页资源管理器 | 8599 |
| `S6` 结果页在列表中打开 | 8599 |
| `S7` 结果页复制路径 | 8599 |
| `S8` 结果页编辑标签 | 8599 |
| `S9` 结果页清除标签 | 8599 |
| `S10` 结果页重命名 | 8599 |

（S1–S10 都要求先搜索出结果页；P1–P4 要求有正在运行的任务；F4–F9 要求先选中文件——
在任意顺序的排列里，这些前置条件很容易被排到前面而落空。）

## 四、真正值得关注的问题（排列下依旧成立）

| # | 问题 | 在 3 步内是否可达 | 说明 |
|---|---|---|---|
| 1 | 目录被当成文件打标签 | 可达（F3 全选 → B2/F8/F9/T1/T2） | 目录写上 ADS 后：✕ 与「编辑标签」对目录直接 return，搜索又只扫文件 → 看得见、改不掉、搜不到 |
| 2 | 改一个文件的标签，整个遍历根缓存作废 | 可达（改标签 → 搜索，4 条排列） | `invalidateCacheForFile()` 反查遍历根 → 整根删除，下次搜索全盘重扫 |
| 3 | 撤销只保留最近一次 | 可达（48 条排列连续两次改标签） | `Ctrl+Z` 只能撤最后一次，属现有设计 |
| 4 | 结果页改完标签，列表不刷新 | 3 步内不可达（需要 选标签+搜索+改标签 共 3 步之外） | S8/S9 之后结果行芯片仍是旧值；不再匹配条件也不会移出 |

## 五、判定规则（与组合版一致）

| 规则 | 触发条件 | 归入 |
|---|---|---|
| R1 页面入口 | 操作入口所在页 ≠ 当前页 | T1 |
| R2 前置条件 | 未选中文件 / 未选标签 / 无结果行 / 无任务 / 无可撤销 | T2 |
| R3 进程终止 | `G4 退出` 之后仍有操作 | T3 |
| R4 撤销覆盖 | 连续两个改标签的操作 | T4 |
| R5 其它 | 以上都不触发 | T5 |

补充约定：任务启动后默认「等它跑完」；只有紧接其后的进度页操作（P1–P4）或点左侧目录（N1）才算「任务进行中操作」。

> 注：这是按代码语义建模的**规则推演**，不是实际运行程序的结论；规则与组合版完全一致，因此两版可横向比较。

# 三连操作逻辑推演

> 只做逻辑判断，未实际执行。

## 选定链

1. **遍历文件**：`E:\Proj` 目录下（不选中子目录，直接点「遍历文件」）
2. **查找文件**：右侧标签库选中「标签A」，点「查找文件」（数据来源=缓存优先）
3. **结果页清除标签**：在结果列表里选中 1 个文件 → 右键「清除标签」→ 确认

## 逐步副作用

**第 1 步（遍历）**
- `dirs` 表写入 `E:\Proj complete=1`
- `filewithlabels` 写入该目录下所有带标签文件（标签串）
- 若 `E:\Proj` 下有 `node_modules` 之类：整棵跳过，写 `excluded=1`
- 不动文件本身（只读 ADS）

**第 2 步（搜索）**
- 命中缓存：`E:\Proj` 走缓存，不再扫盘（结果页显示「结果来自缓存，xx 前遍历」）
- 若第 1 步有跳过目录：结果页脚注「已跳过 N 个目录，其中的文件未参与本次搜索」
- 结果行标签列异步读 ADS 填充

**第 3 步（清除标签）**
- 删除该文件上的全部 ADS（`FileMarker.Owned` + 各标签流）
- 记录撤销前值（`Ctrl+Z` 可恢复）
- 发出「标签已变更」→ `invalidateCacheForFile()` → 反查到包含它的**遍历根** `E:\Proj`
- → `invalidateDirCache("E:\Proj")`：**删除整个根的 `filewithlabels` 行 + `dirs` 行**
- 结果页**不刷新**：该行仍显示旧标签芯片，也仍留在结果列表里

## 会不会出问题：会，3 个

### 🔴 P1. 一次单文件操作，删掉整个遍历根的缓存

`invalidateCacheForFile()` 的语义是"按文件反查祖先根 → 整根失效"。所以：

```
清除 1 个文件的标签  →  E:\Proj 的全部缓存作废
下次搜索 E:\Proj     →  全盘重扫（大目录可能是几十秒级）
```

界面表现只有结果页脚注从「结果来自缓存」变成「结果来自磁盘扫描」，**用户不知道是自己刚才那一步把缓存清掉的**。目录越大、修改越频繁，缓存越难命中，会给人"越用越慢"的感觉。

### 🟠 P2. 结果页状态与磁盘不一致

清除后：
- 该行**标签芯片仍是旧值**（结果页标签列只在 `onShowFilteredFiles` 时异步读一次）
- 如果它原本是因为「标签A」被搜出来的，清除后它**已经不该出现在结果里**，但仍然显示
- 用户可能判断"清除没生效"，或"这个文件还有标签"

### 🟡 P3. 紧跟一次撤销会再清一次缓存

`Ctrl+Z` 撤销 → 标签恢复 → 又触发一次整根失效。连续"清除→撤销→再清除"会让该目录缓存反复作废；同时撤销只保留最近一次操作，"清除"与后续别的打标签操作之间没有栈。

## 建议（按优先级）

1. **把缓存失效精确到文件**：删除该 `filepath` 行，并把 `dirs` 对应行标记 `complete=0`（下次搜索只回退该目录、不整根作废）；整根删除只作兜底。
2. **结果页在标签修改后刷新对应行**：重读 ADS 更新芯片；若不再匹配当前条件，移出结果或标灰并提示"已不再匹配当前条件"。
3. 清除/编辑完成后在状态栏补一句「该文件所在目录的缓存已更新/失效」，让性能变化可解释。

# 另外两组可选链（简述）

## 链 B：搜索中点左侧目录 → 再搜索

1. 点「查找文件」开始长搜索
2. 搜索中在左侧目录树点另一个文件夹
3. 等 1~2 秒看界面

**判定：有问题（逻辑不一致）**
- 第 2 步的代码是：进度页可见时只 `emit sendStop(); return;` —— **既不导航，也不排队**，用户"想去看另一个目录"的意图被吞掉
- 停止后线程仍会发出结果 → 界面被切到**结果页**，用户看到的是自己并不想看的"搜索结果"
- 建议：停止的同时记住目标目录，任务结束后再导航；或至少提示"已停止搜索，请再点一次目录以打开"

## 链 C：标签库删除标签（只删库）→ 搜索 → 查看文件

1. 标签库删除「标签A」，选择「只从标签库删除」
2. 试着在标签库选中「标签A」去搜索
3. 打开某个原本带该标签的文件

**判定：不报错，但存在理解成本**
- 第 2 步：库里已没有该标签，无法再作为搜索条件（只能按其它标签或文件名找）
- 第 3 步：文件上仍显示「标签A」芯片，属于"库外标签"
- 建议：删除标签确认框里明确写"文件上的标签会保留，但之后无法用该标签搜索"；或在标签库提供一个「库外标签」只读分组，把这些名字也列出来供搜索。
